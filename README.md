# ratatosk-core

Ядро децентрализованного мессенджера **Ratatosk** на Rust: sans-io, без
серверов, без учётных записей. Одна библиотека на Android и десктоп,
подключается через UniFFI.

Спецификация лежит рядом и является единственным источником требований:
[v0.1](ratatosk-v0_1-spec.md) и дополнения
[0.2](ratatosk-v0_2-spec.md) · [0.3](ratatosk-v0_3-spec.md) ·
[0.4](ratatosk-v0_4-spec.md) · [фаза 2](ratatosk-phase2-v0_5-spec.md).
Ссылки вида «§7.1» в коде и документах ведут туда.

## Что это

Переписка без посредника. Нет сервера, который хранит сообщения, знает
состав групп или может выключить учётную запись, — потому что нет
учётной записи. Личность — ключевая пара на устройстве; собеседник
находится по одной из шести дорог, и какая из них жива, решает ядро.

**Шесть ступеней связи, один формат кадра.** Локальная сеть, Bluetooth,
меш Yggdrasil, onion поверх Tor, реле Nostr и обычная почта. Ступень
выбирается по достижимости, а не человеком; кадр на проводе один и тот
же, и подслушивающий не видит, какая дорога была выбрана раньше.

**Каналы.** Открытый — по ссылке, ключ прямо в ней; по приглашению —
владелец впускает. История разъезжается роем между участниками
(Plumtree: часть получает блок целиком, часть — только зов), а не
качается у одного владельца. Файлы едут кусками от нескольких
раздающих сразу.

## Состояние

Фаза 1 (переписка один на один) работает на живых устройствах. Фаза 2
(каналы, рой, файлы) собрана и покрыта проверками; часть её проверена
только на стенде.

| Что | Где живёт |
|---|---|
| 1:1-текст, контакты, история, перезапуск | работает на устройствах |
| Группы, каналы, рой, файлы, компаньон | собрано, покрыто, стенд зелёный |
| Живой эфир, чужое железо, дальние задержки | **за человеком, не за прогоном** |

**Зелёный прогон не даёт права говорить, что работает на устройстве.**
Это не оговорка ради скромности: три поломки осени 2026 — «файлы едут
в одну сторону», битые файлы компаньона и его же скорость — нашёл
стенд с живыми устройствами, а не тесты, и все три жили в местах,
которые тесты считали покрытыми. Что именно не покрыто, перечислено
в [`TESTING.md`](TESTING.md) поимённо.

## Сборка

Нужен Rust 1.85 или новее (`rust-toolchain.toml` закрепляет версию).

```sh
cargo build --workspace
cargo test --workspace
```

Живые ступени сидят за признаками и **не входят в `default`**: `bt`
(радио, только Linux), `tor`, `mail`, `nostr`, `ygg-node`. Правка
в такой ветке проходит обычный прогон и ломает сборку тому, кто признак
включит, — поэтому:

```sh
cargo build --workspace --all-features
```

Целевые платформы ставятся по месту; в `rust-toolchain.toml` их нет
сознательно, иначе rustup тянул бы windows-таргет на машину
Linux-разработчика.

```sh
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
```

Сборка под телефон — [`ANDROID.md`](ANDROID.md), под десктоп —
[`DESKTOP.md`](DESKTOP.md); скрипты `tools/build-android.sh`
и `tools/build-desktop.sh`. iOS в списке нет и не будет (§15).

## Устройство

```
crates/
  wire/       формат кадра: заголовок, классы размера, паддинг   §5.5, §7
  crdt/       HLC, OR-Set, окно дедупликации                     §9, §11.2, §12
  crypto/     идентичность, Noise IK, ретчет, AEAD               §3, §8
  codec/      детерминированный CBOR, карточка, конверт          §4, §6, §9.1
  proto/      конечные автоматы без ввода-вывода                 §5.4, §9, §10, §11
  store/      SQLite, FTS5, свёртка                              §12
  transport/  шесть ступеней — единственный крейт с сокетами     §5
  core/       Engine (sans-io), драйвер, тексты §14              §13.3, §14
  ffi/        граница UniFFI для Android и десктопа              §13.3
  bindgen/    генератор биндингов — инструмент сборки            §13.3
  sim/        детерминированная симуляция                        §16
  lab/        консольный стенд для живых прогонов                —
```

Зависимости идут строго вниз: `wire` и `crdt` не зависят ни от чего,
`transport` — единственный крейт с сокетами и рантаймом. Это
проверяется компилятором, а не договорённостью.

`bindgen` вынесен из `ffi` не для порядка: генератор требует признака
`uniffi/cli`, а признаки в Cargo включаются на крейт целиком, а не
на цель. Останься он внутри `ffi`, clap и camino попали бы в граф
зависимостей библиотеки — то есть в `.so`, которая едет на телефон.

### Почему sans-io

§16 требует детерминированной симуляции с виртуальным временем, §17 —
чтобы харнесс делался первым. Ядро поэтому не владеет сокетами
и не читает часы:

```rust
Engine::step(now_ms, input) -> Vec<Effect>
```

Настоящий ввод-вывод живёт в `transport`, симуляционный — в `sim`,
и оба подставляются в одно ядро без правок протокольного кода.
Практическое следствие: «сеть разделилась на неделю» прогоняется
за миллисекунды и воспроизводится по номеру сида.

## Проверки

```sh
cargo test --workspace                 # 1887 проверок, 39 наборов
python3 tools/sweeps/run_all.py        # 33 метёлки; код возврата = число с находками
cargo build --workspace --all-features # предупреждений быть не должно
cargo doc --workspace --all-features --no-deps
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo fmt --all --check
cargo deny check                       # состав зависимостей и извещения RUSTSEC
```

`cargo deny` ставится отдельно (`cargo install cargo-deny --locked`);
в CI он идёт своей работой. Исключения в `deny.toml` — поимённо
и с причиной, и у каждого записано, при каком условии строка
снимается.

Что каждая проверка держит и **чего в наборе честно нет** —
в [`TESTING.md`](TESTING.md). Там же правило, по которому здесь живут:

> **Ни одно нововведение не считается сделанным, пока не покрыто
> проверками настолько, насколько это возможно.** И каждая написанная
> проверка обязана быть показана красной: сломай то, что она стережёт,
> и убедись, что она падает.

Правило заведено по цене, которую проект заплатил: неделя разбора
на четыре поломки подряд, и все четыре выглядели снаружи одинаково —
«функционал есть, но работает через раз». Метёлка `unused_params`
полгода зеленела, проверяя ноль файлов.

**Метёлки** (`tools/sweeps/`) — проверка текстом того, что некому
проверить сборкой: правила, живущие между двумя исправными половинами.
Одна метёлка — одно правило, названное словами; молчание не считается
чистотой, метёлка обязана печатать, сколько мест осмотрела.

Фаззинг — `cargo fuzz run frame_parse`, цели в `fuzz/` (отдельное
рабочее пространство, нужен nightly).

## Криптография

Noise IK для рукопожатия, X25519 и Ed25519 (dalek), ChaCha20-Poly1305,
BLAKE3 для вывода ключей. Состав стека зафиксирован в `deny.toml`
и проверяется `cargo deny check`: `native-tls` и OpenSSL запрещены
намеренно — arti собирается с `rustls`, а OpenSSL пришлось бы
кросс-компилировать под Android.

**Это не прошедший аудит продукт.** Реализация написана по
спецификации и покрыта тест-векторами (`crates/crypto/tests/vectors/`,
они лежат в репозитории нарочно: изменение такого файла в диффе —
сигнал, что кто-то поменял деривацию). Внешнего криптоаудита не было.

## Чего здесь нет

Список из §15 действует и на код: звонки, iOS, STUN/TURN, MLS/TreeKEM,
персоны, отзыв ключей. Заглушек под них в дереве нет сознательно —
пустой модуль читается как обещание.
