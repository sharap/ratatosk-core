# Ядро на десктопе: сборка и то, обо что спотыкаются

Документ про одно: как довести ядро до приложения на Kotlin Compose и что
на этом пути устроено не так, как на Android. Про саму границу — что клиент
может и что обязан показать человеку — написано в `FFI.md`, раздел
«Компаньон: второй экран», и повторять это здесь незачем.

**Десктоп — компаньон, а не самостоятельный узел (§13.4).** Своей личности,
своего onion-адреса и своей истории у него нет; телефон — единственный
носитель и того, и другого, и третьего. Из этого следует всё дальнейшее,
включая то, чего в сборке нет.

## Чем эта сборка отличается от Android

**Ни `tor`, ни `mail` не включаются.** Компаньон ходит только локальной сетью
(причина в `ARCHITECTURE.md`, 5бб: соединения односторонние, а своего
onion-сервиса у десктопа нет — телефон не может его набрать). Arti в этой
библиотеке был бы десятками мегабайт кода, который никто не позовёт.

**SQLite всё равно собирается, и это осознанная плата.** `ratatosk-core`
зависит от хранилища безусловно, а компаньону хранилище не нужно вовсе.
Сделать зависимость необязательной — отдельная работа по всему ядру, и она
не оправдана ради нескольких мегабайт (`ARCHITECTURE.md`, 5бх). Практическое
следствие одно: для сборки нужен компилятор C.

**Библиотеку грузит JNA, а не `System.loadLibrary`.** Это главное отличие
и главный источник «оно не запускается» — см. ниже.

**Кросс-сборки нет.** Три платформы собираются на трёх платформах или в CI:
для macOS нужен Apple SDK, для Windows свой линкер. Скрипт этого не делает
и не притворяется, что делает.

## Что нужно поставить

```sh
rustup toolchain install stable          # версия — из rust-toolchain.toml
# плюс компилятор C: build-essential / Xcode CLT / MSVC Build Tools
```

## Сборка

```sh
tools/build-desktop.sh
```

Выход:

```text
target/desktop/resources/<префикс JNA>/<библиотека>  → src/main/resources/
target/desktop/kotlin/org/ratatosk/core/*.kt         → src/main/kotlin/
```

Обе половины обязаны быть **из одной сборки**. Биндинги генерируются
по собранной библиотеке (`--library`), а не по исходникам: сгенерированные
отдельно, они однажды разойдутся с тем, что лежит в файле, и расхождение
вылезет не при сборке, а при первом вызове.

В конце скрипт печатает список импортов сгенерированного кода. Он не написан
в скрипте заранее и не написан здесь: набор зависимостей у генератора менялся
между версиями, и утверждать его по памяти — тот самый способ ошибиться,
которого этот проект избегает. `com.sun.jna.*` означает `net.java.dev.jna:jna`,
`kotlinx.coroutines.*` — `kotlinx-coroutines-core`.

## Три вещи, без которых не заработает

### 1. JNA должна найти библиотеку

JNA ищет её в каталоге ресурсов, имя которого зависит от платформы:
`linux-x86-64`, `linux-aarch64`, `darwin-x86-64`, `darwin-aarch64`,
`win32-x86-64`. Скрипт кладёт файл именно туда, и в Gradle остаётся только
не растерять этот уровень вложенности:

```text
src/main/resources/linux-x86-64/libratatosk_ffi.so
src/main/resources/darwin-aarch64/libratatosk_ffi.dylib
src/main/resources/win32-x86-64/ratatosk_ffi.dll
```

**Свериться, а не поверить.** Список выше воспроизведён по памяти о том, как
устроен `com.sun.jna.Platform`, и первый же запуск на новой платформе стоит
начать с одной строки, которая скажет правду:

```kotlin
println(com.sun.jna.Platform.RESOURCE_PREFIX)
```

Если она печатает не то, что лежит в ресурсах, — переименовать каталог
и поправить `case` в `tools/build-desktop.sh`.

Второй путь, годный для отладки: положить библиотеку куда угодно и запустить
с `-Djna.library.path=<каталог>`. Для разработки это удобнее, для сборки
дистрибутива — нет: путь придётся откуда-то брать на машине пользователя.

Признак того, что не нашлась, — `UnsatisfiedLinkError` при первом же
обращении к `RatatoskCompanion`, без внятного объяснения причины.

### 2. События приходят не на UI-потоке

`CompanionObserver.onEvent` зовётся из потока, на котором живёт ядро, — того
самого, что заводит `RatatoskCompanion.open`. Compose обязан получить их
через свой диспетчер:

```kotlin
companion.setObserver(object : CompanionObserver {
    override fun onEvent(event: FfiCompanionEvent) {
        scope.launch(Dispatchers.Main) { model.apply(event) }
    }
})
```

Трогать состояние Compose прямо в колбэке нельзя. Это не совет по стилю:
поток там чужой, и падение будет не в момент ошибки, а позже и в другом месте.

### 3. Ссылку сопряжения хранит приложение

Диска у терминала нет по построению (§13.3): ядро ничего о себе не
записывает. Значит `ratatosk:v0:pair:…` обязано лежать у приложения, и лежать
там, где хранят пароли, — в системном хранилище учётных данных
(`Keychain`, `Credential Manager`, `libsecret`), а не в обычном файле
настроек. **Ссылка и есть секрет сопряжения:** тот, у кого она есть,
становится вторым экраном этого телефона до отзыва.

## Порядок при запуске

```kotlin
val companion = RatatoskCompanion.open(
    inviteUri = savedInvite,     // из хранилища учётных данных
    port = 0.toUShort(),         // пусть выберет система
    peerAddr = null,             // адрес телефона, если mDNS не работает
    cachePath = null,            // снимок на диск не кладём (умолчание §13.4)
    torDir = null,               // свой onion не поднимаем — только общая сеть
)
companion.setObserver(observer)
```

Точные имена и типы даёт **сгенерированный файл**, а не этот пример: регистр
имён, форма конструкторов и то, во что превращается `u16`, — соглашения
генератора, и они менялись между версиями. Открыть `org/ratatosk/core/*.kt`
и посмотреть стоит раньше, чем писать первый вызов.

**Возврат из `open` не означает, что телефон ответил.** Он означает, что
терминал поднялся и здоровается: рукопожатие повторяется по таймеру
с отступлением от секунды до пятнадцати. До события `Linked` окно обязано
показывать «подключаемся», а не пустой список чатов — пустой список это
утверждение, которого никто не делал (§14).

Если телефон не находит десктоп сам (mDNS не работает в этой сети), человек
вводит адрес на телефоне руками — командой из `port()` и `desktopIk()`.
Показать эту строку надо там же, где показывается «не подключается»,
а не прятать в настройках.

## Кэш на диске: что обязательно сказать человеку

По умолчанию не пишется ничего. Включая его, надо сказать прямо, чего это
шифрование **не** даёт: ключ выводится из секрета сопряжения, который лежит
рядом, значит защита работает против скопированного файла и против бэкапа,
но не против того, кто забрал эту машину целиком.

И второе: поднятый из кэша экран показывает то, что было при прошлом
подключении, а не то, что на телефоне сейчас. События `Chats` и `History`
приходят с полем `fresh`; пока оно `false`, на экране обязана быть пометка,
и снимается она первым же ответом телефона.

`setCachePath(null)` **стирает** файл, а не перестаёт его обновлять: человек,
снявший галочку, имел в виду «здесь этого не должно быть».

## Чего в этом документе нет

**Он не проверен сборкой ни разу.** Ни библиотека под десктоп, ни биндинги
для Compose здесь не собирались: у меня нет ни реестра крейтов, ни JVM.
Всё, что выше, выведено из устройства проекта и из того, как устроена
сборка под Android, — то есть это разумная догадка, а не отчёт. Первый живой
прогон вправе поправить в нём что угодно.

Отдельно не описано, потому что за пределами ядра: упаковка дистрибутива
(`compose.desktop.nativeDistributions`), подпись и нотаризация под macOS,
автообновление. Всё это — задачи приложения, и решаются они одинаково
независимо от того, что внутри библиотеки.
